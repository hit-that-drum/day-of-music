# 검색 속도 실측 비교

2026-09-07 실행. 기존 HEAD 버전과 수정된 작업 디렉터리의 실제 GET 핸들러를 각각 실행했다. 검색 로직은 이번 측정 중 변경하지 않았다.

## 조건

- 기준 커밋: `08f03693284bec5591297fbf8eaea7913b587b01`
- 검색어 3개 × 이전/현재 코드 × 2회 = 12회. country=KR, limit=8, type=album.
- 실제 iTunes 네트워크 요청. 모의 응답이나 인위적 지연은 사용하지 않았다.
- TypeScript 핸들러를 Node에서 실행해 요청 시작부터 JSON 결과를 받을 때까지 측정했다.
- Next 서버 시작/컴파일, Data Cache, 브라우저 React Query 캐시, 300ms 디바운스, 화면 렌더링은 제외했다.
- **1회차도 공급자/CDN의 완전한 콜드 캐시를 보장하지 않는다. 2회차는 앱 캐시 적중 시간이 아니라 네트워크 재요청 시간이다.** 공급자 캐시와 연결 재사용은 통제하지 못했다.
- 호출 순서를 교차하고 각 검색 실행 뒤 10초 쉬었다. 첫 연결 준비 비용과 시간에 따른 공급자 지연 차이가 있으므로 적은 표본의 탐색적 비교다.
- 이전 코드의 무제한 대기에는 측정 도구 차원의 20초 안전 제한을 넣었다. 실제로 이 제한에 걸린 요청은 없었다. 현재 코드의 4초 제한은 그대로 적용했다.

## 결과

| 검색어 | 이전 1회 | 현재 1회 | 이전 2회 | 현재 2회 |
|---|---:|---:|---:|---:|
| NewJeans | 3.006초 | 0.993초 | 0.074초 | 0.275초 |
| 자몽살구클럽 | 0.983초 | 4.362초 | 1.598초 | 0.494초 |
| Radiohead Creep | 2.585초 | 1.036초 | 0.090초 | 0.213초 |

전체 6회씩의 산술평균: 이전 **1.389초**, 현재 **1.229초**. 이번 표본에서는 현재가 **11.6%** 짧았지만, 일관된 개선이나 통계적 성능 보장은 아니다. 1회차만 평균하면 이전 2.191초, 현재 2.130초로 차이가 작다.

## 원인과 검색 결과

- 모든 KR 요청이 HTTP 200의 빈 결과여서 국가 fallback을 실행했다. 이번 결과만으로 KR 카탈로그가 항상 비어 있다고 일반화할 수는 없다.
- 이전은 KR → US 앨범 → US 곡 현지화, 총 3회 호출. 현재는 KR → US/JP/GB 병렬, 총 4회 호출이었다. 따라서 이 조건에서는 변경 후 API 호출 수가 오히려 늘었다.
- `자몽살구클럽` 현재 1회차는 KR 356ms, US 370ms에 응답했지만 JP/GB가 각각 4초 타임아웃에 걸렸다. `Promise.all`이 모두 끝나기를 기다려 총 4.362초가 걸렸다. 이전은 0.983초였다. 확보된 결과를 먼저 반환하지 않는 구조가 지연을 만들었다.
- `NewJeans`와 `Radiohead Creep`의 1회차는 현재 코드가 빨랐다. 반복 요청에서는 이전 코드가 더 빨랐다. 공급자/CDN 캐시와 개별 국가 응답 지연의 영향이 크다.
- 두 버전 모두 12회 전부 HTTP 200, 결과 수는 각각 8/1/8개였다. 현재의 상류 요청 두 건에는 타임아웃이 있었다.
- `Radiohead Creep` 첫 결과는 이전 `Radiohead — OK Computer`, 현재 `Radiohead — Creep - EP`였다. 관련도 개선 사례는 있지만 이것만으로 전반적인 정확도 향상을 확정할 수 없다. `자몽살구클럽`은 두 버전 모두 영문 앨범명으로 반환됐다.

## 판단

현재 코드가 항상 더 빠르다고 결론 내릴 수 없다. 우선 개선 대상은 이미 US 결과를 확보해도 느린 JP/GB 응답을 기다리는 fallback이다. 지역 우선순위와 결과 구성 정책을 유지하면서 대기 시간을 제한하는 변경이 필요하다. 이번 요청에서는 측정만 수행했고 검색 동작은 추가 변경하지 않았다.

재실행: `node scripts/benchmark-music-search.cjs` (네트워크 필요; 현재 HEAD와 작업 파일을 다시 비교하고 JSON을 덮어쓴다).

원시 결과: [music-search-benchmark.json](./music-search-benchmark.json). 요청별 URL, 상태, 시간, 응답 크기와 검색 결과명을 포함한다.
