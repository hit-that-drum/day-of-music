# Odesli 공개 프론트엔드 검색 분석

확인일: 2026-09-07. 공개 HTML에 연결된 JavaScript를 다운로드해 분석했다. 서버 내부 구현은 확인하지 않았다.

## 근거

- https://odesli.co/
- 검색/응답 변환: https://odesli.co/_next/static/chunks/9196-e5bf14babc29f2cd.js (모듈 6672)
- URL 판별/플랫폼 구분: https://odesli.co/_next/static/chunks/pages/index-cf542d6355733246.js

## 확인한 동작

1. iTunes `search`에 `term`, `country`, `entity=song,album,podcast,podcastEpisode`를 전달한다. 브라우저 JSONP 요청에 4,000ms 제한이 있다. 비미국 국가 요청이 **오류**일 때 US로 재시도한다.
2. 응답의 `wrapperType`과 `kind`로 곡·앨범·팟캐스트를 구분하고 각 종류의 앞 10개를 사용한다. 앨범은 `trackCount > 1` 조건도 사용한다.
3. 앨범 ID는 `collectionId`, 곡 ID는 `trackId`. 국가 코드는 결과 URL의 첫 경로 구간에서 얻는다. 이미지 크기는 512px로 바꾼다.
4. Spotify 검색 경로도 존재한다. `https://api.odesli.co/search-results`에 `providers`, `query`, `type`, `userCountry`를 전달하고 `x-lt-caller: song.link/web-client` 헤더를 설정한다. 서버 내부 검색/정렬 방식은 이 코드로 복원할 수 없다. 이 프로젝트는 해당 비공개 계약의 API에 의존하지 않는다.

## 정규식의 실제 역할

검색 순위를 계산하거나 원하는 곡을 찾는 정규식은 확인되지 않았다. 확인된 규칙은 다음과 같다.

- URL/URI 입력 구분: `/^https?:\/\/.+\..+/` 또는 `/^spotify:/`
- Apple 플랫폼 구분: `/itun\.es/i`, `/itunes\.apple\.com/i`, `/music\.apple\.com/i`
- 제목의 괄호 구간 추출: `/[[(][^)\]]+[\])]/gi`

마지막 규칙은 일반 제목과 censored 제목의 괄호 구간 개수를 비교한다. 후자가 더 길고 괄호 구간도 더 많으면 후자를 채택해 버전 정보를 보존한다. 예를 들어 일반 제목 `Song`보다 대체 제목 `Song (Live)`를 선택한다. 곡 매칭 알고리즘이 아니다. 플랫폼 구분용 문자열 정규식은 호스트 검증용으로 쓰면 안 된다.

## 프로젝트 적용

기존 코드는 Apple Music 인증 API가 아니라 무료 iTunes Search API를 사용한다.

- 앨범 검색과 추가 곡 검색을 `entity=song,album` 한 번으로 통합했다. 별도 200곡 현지화 요청을 제거했다.
- 곡 검색 결과의 `collectionId`로 앨범을 발견하고 중복을 제거한다. 기존 앨범 선택 → 트랙 펼치기 흐름을 유지한다.
- 통합 응답에 있는 곡의 현지화 앨범명을 활용하고 괄호 버전명 선택 규칙을 재구현했다.
- 요청당 4초 제한. 선호 국가에 결과가 없거나 오류면 나머지 US/KR/JP/GB를 중복 없이 병렬 조회한다. 이는 Odesli와 다른 프로젝트의 지역 보완 정책이다. 전체 상류 대기는 통상 두 단계, 최대 약 8초이나 프레임워크/전송 시간은 별도다.
- 한 시간 상류 캐시를 유지한다. 캐시 없는 검색에서는 선호 국가 한 번, fallback 발생 시 최대 다섯 번 호출하므로 공급자의 호출 제한 가능성은 남는다.
- 입력 변경에 따른 브라우저 요청 취소와 검색어 간 오래된 결과 표시 문제를 수정했다.

별도 Spotify 연동, 전 세계 카탈로그 통합, 정교한 관련도 재정렬은 구현 범위에 포함하지 않았다. 선호 국가에 결과가 있으면 해당 결과를 사용한다. 외부 공급자 응답 속도와 Next 개발 서버 최초 컴파일 시간은 이 변경으로 없앨 수 없다. 실제 사용자 환경의 전후 시간 측정은 수행하지 않았다.

## 검증

`npm run typecheck`, `node scripts/test-music-search.cjs` 및 변경 파일 대상 ESLint로 검사한다. 테스트는 통합 요청 횟수, 현지화, 곡으로 앨범 찾기, 곡 ID, 국가 fallback, 빈 결과와 오류를 모의 응답으로 확인한다.

## 후속 개선: fallback 조기 반환

국가별 응답을 전부 기다리던 `Promise.all`을, 결과가 있는 첫 응답을 채택하는 `Promise.any`로 변경했다. 선호 국가를 먼저 조회하는 정책은 유지한다. 대체 국가의 빈 결과·오류는 승자로 취급하지 않고, 결과 확보 후 나머지는 취소한다. 모든 국가가 실패하면 502, 하나라도 정상 응답했지만 결과가 없으면 빈 목록, 요청자 취소는 408로 구분한다.

대체 국가 결과를 US→JP→GB 순서로 병합하던 기존 방식과 달리, 먼저 응답한 한 국가를 사용한다. 따라서 같은 검색어도 네트워크에 따라 결과 국가/순서가 달라질 수 있다. 선호 국가가 느린 경우의 첫 대기는 여전히 최대 4초다. 병렬 요청 자체는 발생하므로 취소한다고 공급자 호출 수까지 줄어드는 것은 아니다.
